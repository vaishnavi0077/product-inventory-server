# Product Inventory Management Server

A REST API for managing product inventory, built with **Node.js (built-in `http` module)**, **TypeScript** and **ES Modules**. No web frameworks. Data is persisted to a JSON file.

## Features

- Create, read, update and delete products
- Track stock quantity
- Filter by category and stock availability
- Input validation with clear error messages
- JSON file persistence (`node:fs/promises`)
- Layered structure: router, controller, validator, service, repository

## Requirements

- Node.js **20.12 or newer**
- npm
- [Postman](https://www.postman.com/downloads/) (or any API client)

## Setup

```bash
git clone https://github.com/<your-username>/product-inventory-server.git
cd product-inventory-server
npm install
```

Create a `.env` file by copying `.env.example` (PowerShell: `copy .env.example .env`).

| Variable    | Default              | Description                   |
|-------------|----------------------|-------------------------------|
| `PORT`      | `3000`               | Port the server listens on    |
| `DATA_FILE` | `data/products.json` | Path of the JSON storage file |

If `.env` is missing, the defaults are used.

## Running

```bash
npm run dev      # development: runs TypeScript directly, restarts on changes
npm run build    # compiles to dist/
npm start        # runs the compiled server
```

The server starts at `http://localhost:3000`.

## Project structure

```
src/
├── server.ts          # creates the HTTP server, reads PORT
├── app.ts             # request handler + global error handling
├── router.ts          # maps method + path to controllers
├── config/            # PORT and DATA_FILE from process.env
├── controllers/       # handle each endpoint
├── validators/        # validate request bodies and query params
├── services/          # business logic: ids, timestamps, filtering
├── repositories/      # read/write the JSON file
├── types/             # TypeScript interfaces
└── utils/             # http helpers, custom errors
data/products.json     # persistent storage
```

Flow: `server → app → router → controller → validator + service → repository → products.json`

## Product model

| Field           | Type   | Notes                            |
|-----------------|--------|----------------------------------|
| `id`            | string | UUID, generated by the server    |
| `name`          | string | required, 1-100 characters       |
| `category`      | string | required, 1-100 characters       |
| `price`         | number | required, 0 or greater           |
| `stockQuantity` | number | required, non-negative integer   |
| `createdAt`     | string | ISO timestamp, set on creation   |
| `updatedAt`     | string | ISO timestamp, changes on update |

## API endpoints

| Method | Endpoint        | Description                      | Success |
|--------|-----------------|----------------------------------|---------|
| GET    | `/health`       | Server status                    | 200     |
| POST   | `/products`     | Create a product                 | 201     |
| GET    | `/products`     | List products (supports filters) | 200     |
| GET    | `/products/:id` | Get one product                  | 200     |
| PATCH  | `/products/:id` | Update one or more fields        | 200     |
| DELETE | `/products/:id` | Delete a product                 | 200     |

**Filters** for `GET /products` (can be combined):

| Parameter  | Values           | Meaning                                           |
|------------|------------------|---------------------------------------------------|
| `category` | any text         | Case-insensitive match                            |
| `inStock`  | `true` / `false` | `true`: stock greater than 0. `false`: stock is 0 |

## Validation and error handling

Errors are returned as JSON:

```json
{ "error": "Validation failed", "details": ["price must be a non-negative number"] }
```

| Status | When                                                                                   |
|--------|----------------------------------------------------------------------------------------|
| 400    | Missing/invalid fields, unknown fields, invalid JSON, empty PATCH, invalid query param |
| 404    | Product not found, or route does not exist                                             |
| 405    | Route exists but method not allowed                                                    |
| 413    | Request body larger than 1 MB                                                          |
| 500    | Unexpected error (logged on the server, not sent to the client)                        |

**Rules:** `name` and `category` are non-empty strings (trimmed). `price` is a finite number, 0 or greater. `stockQuantity` is a non-negative integer. `id`, `createdAt` and `updatedAt` cannot be set by the client. `PATCH` needs at least one valid field.

**Error requests to try:**

| Request                        | Body                                                          | Expected                        |
|--------------------------------|---------------------------------------------------------------|---------------------------------|
| `POST /products`               | `{"name":"","price":-5,"stockQuantity":2.5,"id":"x"}`         | 400, list of 5 problems         |
| `POST /products`               | `{bad json}`                                                  | 400, body must be valid JSON    |
| `PATCH /products/<id>`         | `{}`                                                          | 400, provide at least one field |
| `GET /products?inStock=maybe`  | none                                                          | 400, invalid query parameter    |
| `GET /products/does-not-exist` | none                                                          | 404                             |
| `GET /orders`                  | none                                                          | 404, route not found            |
| `PUT /products/<id>`           | none                                                          | 405                             |

## Data persistence

Products are saved in `data/products.json` and survive restarts: create a product, stop the server (`Ctrl+C`), run `npm run dev` again, and `GET /products` still returns it.

Writes go to a temp file first and are then renamed over the real file, so a crash cannot leave a half-written file. Writes are queued one at a time so simultaneous requests cannot overwrite each other.

## Design notes

- **Layers:** controllers handle HTTP, services hold business logic, and only the repository touches the file system.
- **Errors:** handlers throw custom errors (`ValidationError`, `NotFoundError`), and one `try/catch` in `app.ts` turns them into responses.
- **Imports:** relative imports use the `.js` extension, as required by Node's ES Modules (`NodeNext`).
